# ADR-003: Hybrid synthetic + hand-crafted dataset of ~75 questions

**Status:** Accepted (dataset currently synthetic — see note)

## Context

A RAG eval is only as good as its questions. Two failure modes to avoid:
purely-synthetic sets (which test what an LLM finds easy to ask, not what is
hard) and tiny hand-written sets (which lack coverage). We also need ground-truth
answers and the set of relevant chunk ids per question to score retrieval.

## Decision

- Target **~75 questions**: large enough for per-slice signal, small enough to
  curate by hand and to keep judge cost bounded.
- **Hybrid construction:** ~60 generated-then-curated questions for coverage,
  plus **15 hand-crafted hard cases** drawing on domain expertise — the cases
  that surface failures the synthetic set misses.
- Tag each question with `difficulty`, `question_type`, and `is_hard_case` so the
  dashboard and aggregator can break results down by slice.
- A CI validator (`dataset/validator.py`) enforces that every
  `relevant_chunk_ids` entry exists in the corpus manifest and that ids are
  unique — a dataset that references missing chunks would silently zero out
  retrieval metrics.

## Note — current data is synthetic

The committed dataset and results are **synthetic placeholders**
(`SYNTHETIC-DEMO`) generated by `scripts/generate_synthetic_data.py`, because the
corpus used during development was throwaway test data. The construction
*method* above is what a real run would follow; the synthetic set mirrors its
shape (75 questions, 15 hard cases, slice tags) so the harness, dashboard, and
notebook are exercised end-to-end.

## Consequences

- **Small N (75).** Limited statistical power; per-slice numbers rest on few
  questions. Treated as a first-class limitation in reporting.
- **Single domain.** Findings may not transfer beyond clinical guidelines.
